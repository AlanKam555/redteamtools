# Checklists

> Authorised use only. [Disclaimer](../DISCLAIMER.md) · [Security policy](../SECURITY.md) · [Repository index](../README.md) · [Licence](../LICENSE) · [Contributing](../CONTRIBUTING.md)

These lists are the decisions an authorised assessment has to make before, during, and after testing. Tick an item when the evidence exists, not when someone remembers doing it. A blank box is a gap to close or a limitation to write into the report.

| Checklist | When to use it |
| --- | --- |
| [Scoping](scoping.md) | While the engagement is being agreed. |
| [Rules of engagement](rules-of-engagement.md) | Before the first request is sent. Pair it with the [template](../templates/rules-of-engagement.md) and the [validator](../tools/README.md). |
| [Web application testing](web-application-testing.md) | During an authorised web assessment, next to the [web method](../methodology/05-web-application-testing.md). |
| [API testing](api-testing.md) | During an authorised API assessment, next to the [API method](../methodology/06-api-testing.md). |
| [Reporting](reporting.md) | While the report is drafted and before it is sent. |

None of these lists is a licence to test. The written authorisation is the licence. The list is how you notice that the authorisation does not yet cover what you are about to do.
